# 6.3.1 Adicionando Arquivos à Área de Preparação via \`git add\`

O comando <mark style="color:purple;">git</mark> <mark style="color:orange;">add</mark> é utilizado para preparar mudanças realizadas nos arquivos do projeto. Em vez de registrar imediatamente todas as alterações, o Git introduz uma etapa intermediária em que você seleciona o que fará parte da próxima versão. Essa preparação acontece na **Staging Area**.

Ao utilizar o comando, você não está criando uma nova versão nem alterando o repositório. O que ocorre é apenas a indicação de quais mudanças devem ser incluídas no próximo estado preservado do projeto.

## **Como Funciona**

Durante o trabalho, é comum modificar diversos arquivos. Algumas alterações podem estar concluídas, enquanto outras ainda estão em andamento. O comando <mark style="color:purple;">git</mark> <mark style="color:orange;">add</mark> permite organizar esse processo.\
\
Por exemplo, se você editou um arquivo chamado `index.html`, você usaria <mark style="color:purple;">git</mark> <mark style="color:orange;">add</mark> <mark style="color:green;">index.html</mark> para preparar essas alterações.

O <mark style="color:purple;">git</mark> <mark style="color:orange;">add</mark> é uma etapa intermediária que permite que você **revise** e **selecione** as mudanças antes de salvá-las permanentemente no repositório.

## **Estrutura**

O formato base do comando <mark style="color:purple;">git</mark> <mark style="color:orange;">add</mark> é:

> <mark style="color:purple;">git</mark> <mark style="color:orange;">add</mark> <mark style="color:green;">caminho</mark>

Em que:

* <mark style="color:green;">**caminho**</mark>: refere-se ao local do elemento (arquivo ou pasta) cujas mudanças serão preparadas.\
  Esse argumento pode assumir diferentes formas. Ele pode indicar um arquivo específico, uma pasta inteira ou até múltiplos elementos ao mesmo tempo. Também é possível utilizar caminhos mais amplos, que representam conjuntos de alterações. Em termos práticos, o caminho funciona como uma referência que informa ao Git **quais mudanças devem ser enviadas para a Staging Area**.

## **Exemplos de uso**

* Adicionar um arquivo específico:
  * <mark style="color:purple;">git</mark> <mark style="color:orange;">add</mark> <mark style="color:green;">index.html</mark>
  * Prepara as mudanças feitas em `index.html` para a próxima versão salva.
* Adicionar uma pasta específica:
  * <mark style="color:purple;">git</mark> <mark style="color:orange;">add</mark> <mark style="color:green;">images/</mark>
  * Prepara todas as mudanças feitas dentro da pasta `images/` para a próxima versão salva.
* Adicionar vários arquivos de uma vez:
  * <mark style="color:purple;">git</mark> <mark style="color:orange;">add</mark> <mark style="color:green;">index.html style.css script.js</mark>
  * Prepara as mudanças feitas em `index.html`, `style.css` e `script.js` para a próxima versão salva.
* Adicionar todos os arquivos modificados
  * <mark style="color:purple;">git</mark> <mark style="color:orange;">add</mark> <mark style="color:green;">.</mark>
  * Prepara todas as mudanças feitas em todos os arquivos do diretório atual e seus subdiretórios para o próximo commit.

{% hint style="danger" %}
## Evite utilizar git add .

Um erro muito comum entre iniciantes é usar o comando <mark style="color:purple;">git</mark> <mark style="color:orange;">add</mark> <mark style="color:green;">.</mark> sem revisar as mudanças, o que pode levar a adicionar e comitando arquivos indesejados. Prefira revisar e adicionar arquivos individualmente (<mark style="color:purple;">git</mark> <mark style="color:orange;">add</mark> <mark style="color:green;">arquivo</mark>) para ter mais controle sobre o que está sendo versionado.

**Recomendação**

* :thumbsup: <mark style="color:purple;">git</mark> <mark style="color:orange;">add</mark> <mark style="color:green;">arquivo1 arquivo2...</mark>
* :thumbsdown:  <mark style="color:purple;">git</mark> <mark style="color:orange;">add</mark> <mark style="color:green;">.</mark>
{% endhint %}
